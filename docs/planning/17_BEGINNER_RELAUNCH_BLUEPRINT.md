# Choorai 초보자 리런치 블루프린트 (2026-06-01)

## 1) 왜 개편이 필요한가
현재 사이트는 문서 양 자체는 적지 않지만, 초보자 관점에서 보면 아래 문제가 남아 있다.

- 정보는 많은데 "지금 뭘 해야 하는지"가 페이지마다 일관되지 않다.
- `Map` 중심 탐색은 경험자에게 유리하고, 입문자에게는 선택 과부하를 만든다.
- `Prompt + 산출물 + 완료 기준`이 표준화되어 있지 않아 "완주 경험"이 약하다.

핵심 문제는 콘텐츠의 절대량보다 **행동 단위 설계 부재**다.

## 2) 리런치 북극성
`초보자가 14일 안에 배포 가능한 서비스 URL 1개를 반드시 갖게 만든다.`

이를 위해 Choorai의 중심을 다음처럼 전환한다.

- 기존: 주제 탐색형 문서 허브
- 목표: 미션 완주형 빌드-투-디플로이 가이드

## 3) 제품 구조 전환 (IA)

### Home
- 트랙 선택: Frontend / Backend / Fullstack
- "오늘의 미션 1개" CTA
- 최근 완주 산출물(배포 URL 제출 예시)

### Path
- 60분 완주(입문)
- 2주 미션 로드맵(신규 핵심)
- 이후 코스(미니 SaaS, B2B Admin)

### Map
- 학습 참고용 인덱스 역할로 위치 조정
- 미션 수행 중 필요할 때만 참조하는 백과사전 포지션

### Recipes / Fix
- 미션 실패 시 복구용 도구 모음으로 재포지셔닝
- 각 미션 페이지에서 관련 레시피/트러블슈팅을 직접 연결

## 4) 미션 페이지 표준 템플릿
모든 신규/개편 페이지는 아래 7개 블록을 고정한다.

1. `미션 목표` (1문장)
2. `AI 시작 프롬프트` (복붙 가능)
3. `실행 단계` (최대 5단계)
4. `산출물` (파일/URL/스크린샷)
5. `완료 기준(DoD)` (체크리스트)
6. `검증 명령` (`curl`, URL, 테스트)
7. `막힐 때 이동` (Fix/Recipe 링크)

## 5) 콘텐츠 품질 바 (입문자 기준)
한 페이지라도 아래를 충족하지 못하면 "참고 자료"로 분류하고 메인 미션에서 제외한다.

- 10분~25분 안에 끝나는 단위여야 한다.
- 코드 복붙 후 검증 커맨드가 반드시 있어야 한다.
- 완료 조건은 관찰 가능한 결과(예: URL 접속, API 응답)로 정의한다.
- 프롬프트는 "역할 + 맥락 + 출력 형식"이 포함되어야 한다.
- 실패 시 우회 경로(Fix/Recipe) 링크가 있어야 한다.

## 6) 4주 실행 계획

### Week 1: 구조 고정
- `/path/mission` 공개 (2주 미션 베타)
- 내비게이션에서 미션 트랙을 Path 최상단으로 승격
- 콘텐츠 감사 자동화(`content-audit`) 도입

### Week 2: 미션 1~6 정식화
- 아이디어/스코핑
- 프론트엔드 scaffold
- 백엔드 scaffold
- API 연결
- 첫 배포
- 회고/수정

### Week 3: 미션 7~14 정식화
- 인증/권한 기초
- 관측성 최소셋
- 롤백 시나리오
- 비용 가드레일
- 최종 데모 페이지 제출

### Week 4: 성능/전환 최적화
- 이탈 구간 분석(미션별 완료율)
- 난이도 조정 및 프롬프트 개선
- "초보자 완주율" 기준으로 콘텐츠 재정렬

## 7) 성공 지표
- 7일 내 첫 배포 URL 제출률
- 미션 1→6 완주율
- 미션별 평균 소요 시간
- "막힘 후 복구" 비율 (Fix 진입 후 재완주율)

## 8) 운영 원칙
- 새 문서를 추가하기 전에 기존 미션과의 연결을 먼저 작성한다.
- 설명 길이보다 "검증 가능성"을 우선한다.
- ko/en 동시 공개 원칙을 유지한다.

## 9) 진단 커맨드
개편 전/후를 동일 기준으로 비교하려면 아래 커맨드를 사용한다.

```bash
cd site
node scripts/content-audit.mjs --out=../docs/planning/18_CONTENT_AUDIT_BASELINE.md
```
